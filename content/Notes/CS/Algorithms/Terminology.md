### Fundamental Methods
1. Divide and Conquer
	Divide and Conquer is a family of algorithm that divides the original problem into a set of smaller subproblems, solves the subproblems recursively and combines them to form the solution of original problem. The steps of Divide and Conquer contain: 1. Divide the original problem into a number of subproblems that are smaller instances of original problem; 2. Conquer the subproblems by solving them recursively. If they are small enough, solve them directly; 3. Combine the solutions of the subproblems into the solution of original problem. Divide and Conquer approach reduces problem size of each step, which can lead to better efficiency. An example is merge sort, which sorts the array by dividing it into two halves, sorting each half recursively, and merging the sorted halves.

### Data Structures
1. Red-Black Tree
	Red-Black Tree is a kind of self-balancing binary search tree, for efficient data storage and retrieval. Each node in a Red-Black Tree has a color, either red or black. The key properties of it contain: each node is either red or black, root is black, leaves are black, the children of a red node are black and every path from a node to the leaves in its subtree have the same number of black nodes. When maintain these properties, it can be proved that red-black trees always have $O(logn)$ height, which means we can perform search, insert and delete operations in worst case $O(logn)$ time. When perform insert and delete, we may need to rotate and recolor some nodes to maintain these properties.  The application contains Linux's process scheduler and C++ STL's std::map and std::set.
2. B-Tree
	B-Tree is a kind of self-balancing search tree to maintain sorted data for efficient search, insertion and deletion. It is a multi-way tree, where each node has a variant number of children, with the constraints that each internal node other than the root has at least $t$ children and at most $2t$ children and all leaves have the same depth. It can be proved that under the above constraint, the height of a B-Tree is worst-case $O(logn)$. And the search, insertion and deletion operations can be performed in $O(logn)$ time. When performing insertion and deletion, we may need to split, move or merge the nodes to maintain the constraints. B-Tree is suitable in database and file systems, which can minimize disk I/O. A famous variant is B+ Tree, which only stores data in leave nodes, is commonly used.
